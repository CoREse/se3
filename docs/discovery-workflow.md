# Discovery Workflow

Discovery workflow 是 SE3 的一个新功能，允许在正式开始 analyze 之前，与用户进行多轮对话来探索和澄清需求。

## 使用场景

当你有一个初步的想法，但还不确定具体要实现什么时，可以使用 discovery mode：

```bash
se3 run --discover "我想做一个关于用户认证的功能"
```

## 工作流程

```
User Input → DISCOVERY (多轮对话) → 用户确认 → ANALYZE → ... → 完成
                ↓
         (保存状态，可随时恢复)
```

## 特点

1. **多轮对话**：AI 会通过提问来理解你的需求
2. **渐进澄清**：每轮对话都会加深对问题的理解
3. **状态保存**：对话过程中可以随时中断并恢复
4. **自动生成精炼描述**：确认后自动生成结构化的任务描述

## 使用方式

### 启动 Discovery Mode

```bash
# 方式1: 使用 --discover 参数
se3 run --discover "我想改进我们的日志系统"

# 方式2: 使用 -d 短参数
se3 run -d "我需要添加一个搜索功能"
```

### 对话流程

1. **初始探索**：AI 会根据你的初步描述提出问题
2. **澄清回答**：你回答 AI 的问题，提供更多细节
3. **综合确认**：AI 会总结理解并生成精炼的任务描述
4. **确认继续**：你确认描述后，流程自动进入 analyze 阶段

### 中断和恢复

如果在对话过程中需要退出，可以使用 `Ctrl+C`：

```
Discovery paused. Flow state saved.
Resume with: se3 run --resume
```

之后可以随时恢复：

```bash
se3 run --resume
```

## 示例

### 示例 1：功能探索

```bash
$ se3 run --discover "我想做一个用户管理功能"

Discovery Round 1
============================================================

我理解你想要添加用户管理功能。为了帮助我更好地理解你的需求，
我有几个问题：

🤔 QUESTIONS:
------------------------------------------------------------
  1. 这个用户管理功能是给谁用的？管理员还是普通用户？
  2. 需要支持哪些操作？（创建、删除、修改、查询？）
  3. 有现成的用户数据库吗，还是需要新建？

============================================================

Your response: 给管理员用的，需要CRUD操作，用户数据存在 Postgres 里
```

### 示例 2：确认并继续

```
Discovery Round 3
============================================================

基于我们的讨论，我理解你需要：

1. 一个管理员专用的用户管理界面
2. 支持完整的 CRUD 操作
3. 集成现有的 Postgres 用户数据库

📋 PROPOSED TASK DESCRIPTION:
------------------------------------------------------------
为管理员创建一个用户管理界面，支持对存储在 Postgres 
数据库中的用户进行 CRUD 操作。包括用户列表查看、新增用户、
编辑用户信息和删除用户功能。

Does this accurately capture what you want to build?
Reply with:
  - 'yes' or 'ok' to proceed with this description
  - 'no' or provide corrections/clarifications

============================================================

Your response: yes

[继续到 ANALYZE 步骤...]
```

## 技术细节

### 状态管理

Discovery workflow 使用与其他步骤相同的 flow state 机制：

- 对话历史保存在 `discovery_state` 中
- 每轮对话都会保存到 flow state
- 可以随时通过 `se3 run --resume` 恢复

### 与常规流程的集成

Discovery 完成后：

1. 精炼的描述会传递给 ANALYZE 步骤
2. ANALYZE 使用精炼描述代替原始输入
3. 后续所有步骤与常规流程一致

### 最大轮数限制

为了防止无限循环，discovery 有最大轮数限制（默认 10 轮）。如果达到限制：

- 系统会自动生成一个基于对话历史的描述
- 流程会继续到 ANALYZE 步骤
- 日志中会记录警告信息

## 配置

Discovery 模式目前使用固定的配置：

- `MAX_DISCOVERY_ROUNDS = 10`：最大对话轮数

未来版本可能会支持自定义配置。

## 最佳实践

1. **提供初步想法**：即使是不完整的想法也可以开始 discovery
2. **详细回答**：越详细的回答，生成的描述越准确
3. **及时确认**：当 AI 的理解正确时，及时确认以节省时间
4. **使用恢复**：如果对话被打断，记得使用 `--resume` 继续

## 与其他模式的对比

| 模式 | 适用场景 | 启动方式 |
|------|----------|----------|
| 常规模式 | 需求明确 | `se3 run "具体任务"` |
| Discovery 模式 | 需求模糊 | `se3 run --discover "初步想法"` |
| Quick 模式 | 小修改 | `se3 run --type=small "快速修复"` |

## 故障排除

### Discovery 卡住了

如果 AI 反复问相似的问题：
- 尝试用不同的方式表达你的需求
- 直接告诉 AI "我已经提供了足够的信息，请生成描述"

### 恢复后从头开始

如果恢复后发现从第一轮开始：
- 检查是否有多个 flow 状态文件
- 使用 `se3 status` 查看当前 flow 状态

### 生成的描述不准确

如果对最终生成的描述不满意：
- 在 confirmation 阶段回复 "no" 并提供修改建议
- 或者重新开始 discovery 流程
