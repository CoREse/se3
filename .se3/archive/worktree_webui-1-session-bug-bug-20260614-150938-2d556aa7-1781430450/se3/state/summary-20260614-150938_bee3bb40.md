# Session 报告:修复 webui running-flow 实时视图「消息不显示」bug(#193 遗留另一半)

## 本次完成的工作

本 session 修复了 se3 webui running-flow 实时聊天视图在两种场景下「无法持续/正确显示对话记录」的 bug,对应 #193 遗留的另一半(发送错误显示部分此前已修复)。两个症状均已定位根因并修复:

- **症状 A(普通 session:respond 后实时视图停止追加)** — 根因在 `server/ws.py`:当 `MSG_HISTORY_DATA` 同时命中并 resolve 一个 pending REST pull waiter 时,原逻辑用「一刀切」的 `if not resolved_pull` 抑制了对 `/ws/ui` 的广播,导致 respond 后由 daemon 推来的 `mode: append` 增量被吞掉,实时视图必须退出重进触发 `/api/history` 全量快照才能恢复。
- **症状 B(`--worktree` / discovery session:首条 assistant 正文为空且不再追加)** — 根因在 `daemon/history.py` 的 full-read 路径:对无结尾换行的末行无条件消费,导致 sidecar / terminal 文件首条完整记录与中途写入的截断尾行处理不当;同时 worktree 会话的 `project_root` 在 respond/interject 与 history 读取链路中未被正确保留。

## 关键改动

- **`server/ws.py`**:将「一刀切」的广播抑制 `if not resolved_pull` 改为 `suppress_broadcast = resolved_pull and mode == protocol.HISTORY_MODE_FULL`。这样 `mode: append` 的实时增量**始终**广播到 `/ws/ui`,即便它同时 resolve 了一个 pending REST pull waiter;`mode: full` 命中 waiter 时才抑制。always-broadcast 的去重安全性由前端既有的 `dedupeAppendRecords`(已接入 `app.js:2666` / `app.js:2693` 两个 append 消费点)保证。
- **`daemon/history.py`**:full-read 路径对未结尾换行的尾行改为按 JSON 可解析性分支 —— 完整记录(terminal/sidecar 文件)正常消费,中途写入的截断尾行保持不动(不推进 consumed/offset),待写完后再次读取;`read_active_flows` 的 final-flush pass 通过 `root_by_flow` 映射将 `read_flow` 按各 flow 自身的 `project_root` 作用域化。sidecar(`*.jsonl.from-*`)枚举与 `_logical_step_id` 合并逻辑保持不变。
- **`daemon/client.py`**:respond/interject 从 history index 解析 worktree/discovery session 的 `project_root`,使 `.response` 落到正确的 root 下。
