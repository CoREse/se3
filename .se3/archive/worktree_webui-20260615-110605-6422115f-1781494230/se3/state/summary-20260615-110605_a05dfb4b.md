# 会话报告：修复回复面板「消息详情」展开后滚动位置被重置的问题

## 1. 本次会话完成的工作

修复了 WebUI 停靠回复面板中「消息详情」展开块在自动刷新时滚动位置被反复打回顶部、导致无法下拉阅读长内容的问题。

根因在于 `updateReplyBox(flow)` 每次刷新都对回复上下文区执行 `ctx.innerHTML = ""` 整块重建，由 `buildCollapsiblePrompt` 生成的 `.flow-reply-prompt` 展开块（`style.css` 中 `max-height: 30vh` 内部滚动）随之被重新创建，新建 DOM 节点的 `scrollTop` 归零。叠加 3s 轮询（`detailPollTimer`）与 ws `STATUS_UPDATE` 推送的高频重建，用户的阅读滚动位置被持续重置。

## 2. 关键改动

- 新增会话级映射 `flowReplyPromptScroll`，以 intervention id 为键，记录展开的「消息详情」体的 `scrollTop`。
- 在该详情体上监听 `scroll` 事件持续捕获滚动位置；在自动重建（3s 轮询 / ws `STATUS_UPDATE`）后将其恢复，从而跨刷新保持阅读位置。
- 在 `#flow-view` 打开/关闭时，连同 `flowReplyPromptExpanded` 一起重置滚动状态。

约束均得到遵守：作用范围限定在 `#flow-view` 停靠回复面板的 `buildCollapsiblePrompt` / `.flow-reply-prompt`，未触及 chat-stream 中其他折叠/展开块；刷新机制与频率（3s 轮询、ws 推送）保持原样；`flowReplyPromptExpanded` 的展开/收起跨刷新持久化、首次展开 `scrollIntoView`、收起不滚动等既有行为均未退化。
